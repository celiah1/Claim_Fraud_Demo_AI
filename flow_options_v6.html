ClaimGuard · 3 ways to organise the app

Each option uses one navigation system. The left panel and a top progress bar never repeat the same steps. Click an option to expand or collapse it.

Recommendation: Option C, Home hub + workspaces

Investigators spend their day in one place (the queue) and leaders in another (the dashboard). A hub opens straight into each workspace, and the workspace has only its own few tabs, so there's no long sidebar and no duplicate progress bar. Option A is the best fit if the demo is mainly a guided walkthrough for new viewers.

A

Top stepper only (no left panel)

The 3 stages are the top bar; each stage has a few sub-tabs. Admin pages sit in one menu.

How it works

The top bar is the only navigation: three stages in order, ticked off as you go. Inside a stage, 2–3 sub-tabs. Model Evaluation, Data & Access and How ClaimGuard Works sit under an Admin menu.

Strengths
  • Full page width for the queue and charts
  • Progress is obvious
  • Great for a guided demo
Watch out
  • Daily users click through stages to reach the queue
  • Admin pages less visible
Best for: stakeholder walkthroughs and first-time users.
B

Left panel only (progress built in)

The sidebar holds the stages and shows progress itself. No top bar; each page has a small breadcrumb.

How it works

One left panel holds every page, grouped by stage, with ticks and a small progress bar at the top of the panel. The page itself only shows a one-line breadcrumb, so nothing repeats.

Strengths
  • Every page one click away
  • Closest to today's app, so the least rework
  • Familiar pattern
Watch out
  • Takes ~230 px of width from the queue
  • Long list of pages can feel heavy
Best for: analysts and admins who jump between many pages.
C

Home hub + workspaces (recommended)

Home shows 4 workspaces. Inside a workspace, a slim tab bar lists just its pages, with a Home link back.
